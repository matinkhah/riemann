# Mathematical Decoration Is Not Security: A Critical Analysis of a Zeta-Inspired Key-Derivation Prototype

## ZKD Reproducibility Artifact (zkd_colab.py)

This repository contains the standalone, parallelised Python script used to generate all empirical measurements, key-space statistics, and cross-platform precision metrics presented in the paper:
"Mathematical Decoration Is Not Security: A Critical Analysis of a Zeta-Inspired Key-Derivation Prototype"
Author: S. Mojtaba Matinkhah (Yazd University)
Target Venue: ACM Transactions on Privacy and Security (TOPS)
The script is fully vectorised using NumPy and optimized to execute smoothly within constrained cloud environments such as Google Colab, using its default 2-vCPU configuration.

📊 What this Script Measures

The execution of zkd_colab.py fully populates Table 1 and supports the cryptanalytic arguments in Section 5 of the paper by calculating:
• Effective Key Space & Density: Evaluates the derivation function over high-resolution grids (2× 10⁵ and 4× 10⁵ points) near t₀ ≈ 8.49× 10⁷ to measure input collision rates and map the collapsed keyspace down to ≈ 2⁴³ effective bits.
• Attack Coverage & Grid Efficiency: Models a naive grid search against real targets to calculate actual attacker success probabilities versus structural cell-coverage ratios.
• Raw Stream Statistics: Aggregates byte distributions across 20,000 distinct execution heights to extract Shannon entropy bits per byte and calculate a χ² uniformity divergence test.
• Cross-Precision Disagreement: Directly tracks bit-exact reproducibility drift by processing identical heights through native 64-bit (float64) and x87 80-bit (longdouble) platform math libraries.
• Attacker Throughput: Computes comparative execution scaling on single-core vs. multi-process pools to build realistic hardware resource timelines for total keyspace exhaustion.

📦 Generated Outputs

Every successful run outputs two critical files directly alongside the script:

1. results_colab.json

Contains all precise, raw metrics alongside complete runtime execution metadata (CPU hardware string, active core count, platform architecture, package versions, and random state seeds). This file serves as the verifiable artifact record for submission.

2. results_macros.tex

An autogenerated LaTeX macro library containing a series of \renewcommand definitions.
Instead of copying empirical statistics by hand into your LaTeX manuscript, drop this file into your paper's workspace and reference it directly inside your document preamble:
latex
\input{results_macros.tex}
Use code with caution.
This ensures that the final rendered figures within the text always match your execution data precisely, with no manual copy-paste errors.

🛠️ Architecture & Determinism

• Fixed Work Chunking: Computational steps are split into static-sized array chunks prior to delivery across execution workers. This forces work units to align completely, ensuring output figures do not shift or drift depending on whether you run the script across 1, 2, or more cores.
• Seeded Random State: Random inputs are pulled down in a rigid, sequential order from an isolated, explicitly seeded generator (seed=2026).
• Platform Dependencies: The Cross-precision disagreement metric explicitly hooks into your host environment's underlying C math library compilation (libm). While numeric outputs remain stable, total macro variances here directly monitor native architectural behavior under evaluation.
